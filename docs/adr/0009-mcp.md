# 0009 — MCP: server stdio avviati con la sessione, strumenti in classe "esecuzione"

**Stato:** accettata — provata nell'app con un modello locale vero, Qwen 2.5 7B, e un
server MCP di prova scritto in Node (due strumenti, chiamati entrambi con successo), oltre
che dai test automatici con un server in PowerShell. Non è stata provata con server MCP
pubblicati (npm, PyPI).

## Contesto

AG-7 chiede di aggiungere strumenti esterni tramite MCP (Model Context Protocol) senza
modificare il nucleo. Gli strumenti esterni devono passare per gli stessi permessi, lo
stesso registro e lo stesso ciclo degli altri ([ADR 0007](0007-strumenti-e-permessi.md),
[ADR 0008](0008-agenti-e-terminale.md)).

## Decisione

**Trasporto stdio.** Un server MCP è un programma configurato nelle Impostazioni (nome,
comando, argomenti uno per riga, variabili d'ambiente). L'app lo avvia come processo
figlio, senza finestra, dentro un *job* di Windows, e gli parla in JSON-RPC 2.0, un
messaggio per riga (`crates/core/src/mcp.rs`): `initialize` →
`notifications/initialized` → `tools/list` (con le pagine) → `tools/call`. Alle richieste
del server risponde (`ping`) o le rifiuta ("metodo non supportato"); le notifiche e le
righe che non sono JSON vengono ignorate. Su Windows i comandi senza estensione si cercano
nel `PATH` con `PATHEXT`, così anche `npx` (che è `npx.cmd`) parte.

**Server per agente, avviati con la sessione.** Ogni agente sceglie quali server usare.
All'inizio di ogni sessione (e a ogni ripresa) i suoi server partono, nella prima
cartella di lavoro se c'è; a fine sessione il job li chiude. Se un server non parte, la
sessione si ferma con un errore che riporta le ultime righe scritte dal server:
meglio di un agente che lavora senza i suoi strumenti. Il pulsante **Prova** delle
Impostazioni avvia il server, ne elenca gli strumenti e lo chiude.

**Nomi.** Il modello vede `mcp__<server>__<strumento>`, con i soli caratteri ammessi dai
servizi e al massimo 64 caratteri; lo schema dei parametri diventa sempre un oggetto.

**Permessi: tutti gli strumenti MCP sono di classe "esecuzione".** Un server è un
programma che fa ciò che vuole, e le sue indicazioni (`readOnlyHint` e simili) le scrive
lui: per SI-5 non possono allentare i controlli. Quindi chiedono conferma con "Chiedi
sempre" e con "Consenti modifiche ai file", e partono da soli solo con "Consenti tutto".
Nella richiesta di conferma si vedono server, strumento e parametri.

**"Consenti sempre" vale per un solo strumento.** Per gli strumenti dell'app alza il
livello della conversazione (ADR 0007); per uno strumento MCP invece lo aggiunge a
`allowedTools` della sessione e il livello non cambia: approvare `conta_parole` non deve
dare via libera al terminale o agli altri strumenti del server.

**Risultati.** Il testo dei blocchi `text` e delle risorse testuali torna al modello
(al massimo 30.000 caratteri); immagini e audio vengono solo segnalati; `isError`
diventa un errore. Il preambolo del prompt di sistema ricorda già che i risultati degli
strumenti sono dati, non ordini.

**Solo agenti.** In chat i server MCP non si offrono, come il terminale.

## Alternative scartate

| Alternativa | Motivo |
|---|---|
| Trasporto HTTP ("streamable HTTP") | Serve per server remoti con autenticazione (OAuth): utile ma più grande; stdio copre i server locali, i più diffusi. Da aggiungere più avanti |
| Un processo per server condiviso da tutte le sessioni | Sessioni in parallelo si contenderebbero lo stesso server e il suo stato; avviarlo per sessione costa un po' di tempo, ma isola |
| Fidarsi di `readOnlyHint` per non chiedere conferma | L'indicazione viene dal server stesso: un dato non può concedere permessi (SI-5) |
| "Consenti sempre" che alza il livello a "Consenti tutto" | Un clic su uno strumento innocuo aprirebbe terminale e strumenti degli altri server |
| Crate SDK MCP ufficiale | Il protocollo usato è piccolo; un client proprio evita dipendenze pesanti e resta sotto il nostro controllo nei permessi |
| Sessione che continua senza un server che non parte | L'agente lavorerebbe senza strumenti che l'utente si aspetta, e l'errore passerebbe inosservato |

## Conseguenze

- Ogni sessione con server MCP paga il loro avvio (con `npx` la prima volta anche il
  download, entro 90 secondi).
- Le variabili d'ambiente dei server (spesso chiavi API) stanno nell'archivio SQLite, non
  nel Gestore credenziali: l'interfaccia lo dice. Da spostare nel portachiavi se diventa
  comune.
- Uno strumento MCP lento si interrompe dopo 5 minuti; "Ferma" lo interrompe subito, e il
  server viene chiuso con la sessione.
- Se un server viene eliminato dalle Impostazioni, gli agenti che lo usavano lo segnalano
  nell'editor e le loro sessioni non partono finché non lo si toglie.
- Risorse e prompt MCP (oltre agli strumenti) non sono gestiti.
